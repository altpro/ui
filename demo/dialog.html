Dialog

.dialog on a native dialog. Inside, it is a card: header, footer, divided and media all work the same. Buttons open and close it with command and commandfor, so there is no JavaScript. Esc closes it, focus is trapped, and the page behind cannot be reached.

Modal with a close button

Delete this project?

This removes every deployment and cannot be undone.

Type the project name to confirm. Members lose access as soon as you press delete.

The cross is a btn ghost sm after the hgroup, so the card header pushes it to the far side. aria-labelledby on the dialog names it after its heading.

<button class="btn primary" command="show-modal" commandfor="confirm">Delete project</button>
<dialog id="confirm" class="dialog" aria-labelledby="confirm-title">
  <header>
    <hgroup><h3 id="confirm-title">Delete this project?</h3><p>This cannot be undone.</p></hgroup>
    <button class="btn ghost sm" command="close" commandfor="confirm" aria-label="Close">…x…</button>
  </header>
  <p>Body.</p>
  <footer class="justify-end">
    <button class="btn ghost" command="close" commandfor="confirm">Cancel</button>
    <button class="btn danger" command="close" commandfor="confirm">Delete</button>
  </footer>
</dialog>

The dialog is capped at the viewport minus a gap on each side and scrolls inside. The header and footer scroll with the body; there is no pinned header.

A form

Invite a member

The form wraps the fields with class="contents" so they stack with the card gap, and method="dialog" closes the dialog on submit. The footer stays a direct child of the dialog; its submit button points at the form with form="invite". autofocus on the first field puts the cursor there on open; without it the close button takes focus. max-w-sm narrows it.

<dialog id="d" class="dialog max-w-sm" aria-labelledby="d-title">
  <header>…</header>
  <form id="invite" method="dialog" class="contents">
    <div class="field">…<input class="input" autofocus></div>
  </form>
  <footer class="justify-end">
    <button class="btn ghost" command="close" commandfor="d">Cancel</button>
    <button class="btn primary" form="invite">Send invite</button>
  </footer>
</dialog>

Closing and non-modal

Light dismiss

closedby="any". A click on the backdrop closes it, as does Esc.

Session expired

closedby="none". Esc does nothing. The only way out is a button.

Non-modal

popover="manual" on the dialog, opened with command="show-popover". No backdrop, the page stays usable, Esc does nothing. Centred in the viewport.

Default is Esc only. closedby="any" adds the backdrop click, closedby="none" removes Esc. For non-modal, make the dialog a popover="manual" and open it with command="show-popover"; close with command="hide-popover". There is no non-modal command for a plain dialog.

Dashboard Invoices Customers Settings

drawer makes the dialog a full-height panel that slides in from the end edge; drawer start comes from the start edge. Everything else is the same: commands, closedby, header, footer, divided. Width is 24rem, so w-80 or max-w-sm change it. mt-auto on the footer pins it to the bottom.

<dialog id="filters" class="dialog drawer divided" closedby="any" aria-labelledby="filters-title">
  <header>
    <h3 id="filters-title">Filters</h3>

  </header>
  …fields…
  <footer class="mt-auto justify-end">
    <button class="btn primary" command="close" commandfor="filters">Apply</button>
  </footer>
</dialog>
