Combobox

Combobox.vue: the one component for anything a native <select> cannot do: a long list to search, a list on the server, several values, or adding a new one. A native select stays the answer for one pick from a short fixed list. A trigger styled like .input shows the value and opens a .dropdown. Vue only. A hidden <select> submits the value under name (name[] with multiple).

One from a short list

The trigger is the combobox and keeps focus: arrows, Home and End move through the options, Enter or Space picks, Escape closes, typing jumps to a label. required sets aria-required only; the server validates. disabled cannot open and submits nothing.

<Combobox v-model="status" name="status" label="Status" :options="statuses" required />

A long list

Over 12 options, a search box appears and filters locally. searchable or :searchable="false" overrides that either way. The search box is the combobox now; the first match is highlighted, so Enter takes it.

<Combobox v-model="assigneeId" name="assignee_id" label="Assignee" :options="people" />

Several

multiple: a panel of checkboxes that stays open while ticking. The trigger lists the picks and, from two, a count. The clear button sits beside it. max disables the rest once that many are picked; say so in a hint.

<Combobox v-model="days" name="days" label="Delivery days" :options="days" multiple :max="2" />

Several, with search

With search, multiple is a listbox of options with aria-selected and a checkmark. Enter or a click toggles one and the panel stays open.

<Combobox v-model="tagIds" name="tags" label="Tags" :options="tags" multiple :max="5" />

On the server

src: the search runs on the server and the search box always shows. A URL gets GET src?q=acme by plain fetch, with Laravel's XSRF-TOKEN cookie sent as X-XSRF-TOKEN, and answers [{ value, label }]. A function (q) => Promise covers any other request; this one is a pretend server. Typing waits 250ms, and an answer to an older query is dropped. Opening the panel asks for the empty query, so the server decides what to offer first (recent, favourites, the first few). Return a limited list: the panel shows all it gets. options holds the labels of what is selected, so "Acme Ltd", not 42, shows before any search.

<Combobox v-model="order.customer_id" name="customer_id" label="Customer"
    src="/customers/search" :options="[{ value: order.customer.id, label: order.customer.name }]" />

Adding one

create turns search on and offers "Add “xyz”" when nothing matches exactly, ignoring case. A URL gets POST create with { label } and answers { value, label }, which is selected; a 422 shows its error in the panel. The server decides whether to create or return an existing record, and owns permissions. A function (label) => Promise works too; its rejection's message shows. Try a label under three letters.

<Combobox v-model="post.tags" name="tags" label="Tags" multiple
    src="/tags/search" create="/tags" :options="post.tags_options" />

The same with URLs. This page has no server, so it shows the error state.

Forms

Without v-model, inside a form that owns its data, the value given is the starting value. A native reset and Inertia's reset() put it back, as they would a select. form="id" ties it to a form elsewhere on the page.

VoiceOver check

Checked on Safari with VoiceOver (Cmd+F5) in October 2026; run it again after changing the roles or keyboard. Use Tab and the keys named, not the VoiceOver cursor. For each, note exactly what is spoken.

  1. Trigger, closed. Tab to "Status" in the first section. Expect the label, the value and the role: "Status, In review, pop-up button" or similar. Tab to "Assignee" (empty), "Sizes" (Medium) and "Customer" (Acme Ltd): each should say its label and its value, and nothing when empty. Disabled "Locked status" should say dimmed.
  2. One from a short list. On "Status", press Down. Expect it to open and say the highlighted option ("In review, selected" or similar). Down, Up, Home and End should each speak the new option. Type "a": "Archived". Enter: it closes and the trigger says the new value. Escape on an open list closes it without a change.
  3. A long list. On "Assignee", press Enter. Expect the search box to be announced ("Search Assignee, combo box" or similar). Type "ja": VoiceOver should say the highlighted option ("Jack Wilson"). Down and Up should speak each option. Enter picks it, closes and returns to the trigger, which says "Assignee, Jack Wilson".
  4. Several, checkboxes. On "Sizes", press Enter, then Tab: "Small, checkbox, unchecked". Space ticks it and the panel stays open. Escape closes and the trigger says "Sizes, Small, Medium".
  5. Several, with search. On "Tags" (with search), press Enter, type "c", Down to "CSS" and press Enter. Expect "CSS, selected" (or a change in its selected state) and the panel to stay open. Enter again unticks it. On the trigger, the count is visual only; check it is not read.
  6. On the server. On "Customer", type "mar". Expect "Searching…" and then the first result to be spoken. Type "fail": "Could not load results." should be read. Type "zzz": "No results".
  7. Adding one. On "Tags" in Adding one, type "ab": "Add “ab”" is highlighted. Enter: "The label must be at least 3 characters." should be read. Type "abc" and Enter: it is added and selected.
  8. Report back anything not spoken, spoken twice, or spoken late, especially the options in steps 2, 3 and 5: aria-activedescendant is where VoiceOver has been patchy.
